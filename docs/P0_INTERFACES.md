# P0 artifact and readiness interface

`prepare-data` loads and strictly validates `configs/benchmark.json`, `configs/methods.json` and `configs/uit.json` before opening the dataset. Override file locations with `--benchmark-config`, `--methods-config`, and `--deployment-config`; research values remain fixed. Canonical validated values and SHA-256 identities are frozen in `splits/configuration.json`. Actual environment and model resolution remains later work.

Use `geobench.data.publish_readiness(dataset_root, artifact_root, records, evidence_files, owner_token=...)` to import observations. It performs no network access or UIT inspection. `records` contains exactly `V01`, `V02`, and `V04`; each has `status: verified` and a nonempty `evidence_files` list referencing byte contents supplied in the `evidence_files` dictionary. Paths are relative, canonical and contained. Invalid records cannot publish a lock.

Required record fields:

- V01: `dataset_root`, `ssh_target`, `login_host`, `workspace`, matching the separately confirmed private site identity.
- V02: `artifact_root`, positive integer `free_bytes`, `free_inodes`, `required_bytes`, `required_inodes`; available capacity must cover requirements. Include nonempty `model_cache_paths` and true `quota_ok`, `compute_visible`, `atomic_publication`, `single_writer` observations.
- V04: `fingerprint`, `images`, `classes`, `decoder` (Pillow version), and `checks` with true `readable`, `file_hashes`, `pixel_hashes`, `duplicate_labels`, `quotas`, `leakage`. Compute inventory/fingerprint using `inventory`/`inventory_fingerprint`, and validate allocation with `split_inventory`. Attach actual audit evidence; a verified status alone is insufficient.

The producer recomputes inventory identity and duplicate/quota feasibility, validates all records, then freezes `deployment/data_readiness/lock.json`. `prepare_data` repeats the audit and verifies that evidence against the actual root, decoder and fingerprint before publication. Fixtures supply temporary images and simulated site observations through this same interface; they do not establish real UIT verification. V01/V02 observations remain the operator/preflight producer's responsibility.

A nonempty retained owner token is required before production mutation. Set `GEOBENCH_OWNER_TOKEN` to a privately retained job credential for CLI recovery. The programmatic equivalent is `prepare_data(..., owner_token=...)`. `claim_writer` returns a string-compatible `WriterToken` that holds an OS lease through staging and publication. Keep it alive on its owning thread; close it explicitly when abandoning work. Publication closes it automatically, and process exit releases the OS lease without removing the persistent claim. A same-token concurrent process cannot resume while the lease is active. No PID-based takeover occurs. Losing the credential requires explicit operator recovery, never automatic reclaim.

Writer initialization now persists `.writer.intent` with the identity and token commitment before constructing the claim directory. Matching credentials can finish interrupted intent/claim prefixes and staging initialization under the same OS lease. Mismatched bytes remain blocking. Legacy claims without an intent still require valid existing claim metadata; absent legacy ownership evidence is not guessed. Training leases are scoped to individual run roots, permitting independent processes to execute different runs concurrently.

Production CLI interfaces added after P0 are documented in [PIPELINES.md](PIPELINES.md). Training schema 3 includes Mixup state and a complete CPU-serialized best-epoch snapshot, allowing deterministic publication recovery across device reloads. Earlier schemas are rejected. The frozen validation metric snapshot is `training_metrics.json`; the root `metrics.json` remains mutable until final evaluation publication and is covered by the evaluation lock rather than the training lock.

Authoritative lock basenames are `lock.json`, `pool_lock.json`, `checkpoint_lock.json`, `selection_lock.json`, `bank_lock.json`, `feature_lock.json`, `mining_lock.json`, `evaluation_lock.json` and `report_lock.json`. Hidden staging files use private validation and cannot satisfy a dependency or CLI verification. Cross-stage verification requires an explicit trusted root (`verify ... --root ...`). E0 membership is frozen as `pools/E0/pool.json` and `pool_lock.json`, referencing the shared `train.csv` without copying images.

Official descriptor IDs are `E0/42`, `E1E2/123`, `E3-A1/2026`, etc. Files reside at `runs/<condition>/seed_<seed>/descriptor.json`, with exact fields `run_id`, `condition`, `seed`, `dependencies`. Every dependency record has `path`, `sha256`, `identity`. Required roles are data, pool, runtime, initialization and spec; augmented conditions add strength and e1; E3 adds references, and A2–A4 add mining. Runtime identity is `shared-runtime`, initialization is `initialization:<seed>`, spec is `spec:<condition>`, and remaining role identities are `selected-strength`, `e1`, `reference-bank`, `mining`. Data uses `common-data:<fingerprint>`; E0 pool uses `e0:<fingerprint>`, augmented pools use `pool:<condition>`, and A4 uses A3's pool identity. These are descriptor contracts only, not implementations or execution of later stages.

Descriptor lineage is verified as well as individual hashes: pools must reference the declared data lock, initializations the declared runtime, augmented pools their declared shared inputs, references the declared data/strength, and mining the declared reference bank. Independent claims cannot share a live lease, including on one thread; only nested internal operations are reentrant. Readiness imports validate before claiming and support authenticated idempotent resume.


F06–F09 clarifications:

- Recovery appends only the missing suffix when a private temporary file is an exact byte prefix of its expected content. Symlinks and extending multiply linked temporary files are rejected. Unexpected content is preserved; published outputs/locks must match exactly and are never repaired by overwriting or refreshing hashes.
- `load_config`, `verified_configuration` and programmatic `prepare_data(configuration=...)` use the same validators. Programmatic snapshots require exactly the benchmark, methods and deployment roles plus matching canonical hashes. Research booleans cannot be replaced with numbers; deployment fields have explicit types. Missing deployment measurements remain `null` until separately resolved.
- Before readiness publication, privately materialize `deployment/private_site/lock.json` with identity `private-site`. Its locked `site.json` has exactly `status`, `ssh_target`, `login_host`, `workspace`, `evidence_files`: status must be `verified`, connection/workspace strings nonempty, and evidence_files must reference nonempty supporting observations included in the lock. Use the existing claim/staging/publication API to import separately verified private observations. Keep this profile and evidence out of Git. No private-site producer, connection, or UIT inspection is implemented in P0.
- V01 connection/workspace fields must match that verified private profile. The readiness lock includes its exact hash as a dependency, so a changed or missing private profile blocks downstream data consumers. Fixtures use fictional values and temporary roots, never real deployment evidence.

Implementation can use synthetic datasets and simulated evidence to exercise these contracts locally; actual UIT deployment evidence is a separate milestone and remains required before real publication or scientific workloads.
