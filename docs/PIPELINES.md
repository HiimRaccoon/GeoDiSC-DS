# Local production interfaces

The commands below are implemented interfaces, not records of UIT verification or scientific execution. Run them against a new artifact root with a privately retained `GEOBENCH_OWNER_TOKEN`. Model snapshots, private deployment observations and generated artifacts stay outside Git.

- `stage-model --role classifier|diffusion|dino --snapshot PATH --descriptor JSON --root ROOT` materializes an already verified local snapshot. The descriptor has repository, immutable revision and full file SHA-256 inventory. `--cache-root` explicitly permits trusted cache file links. No model fallback or download is performed.
- `freeze-specs --root ROOT` freezes the confirmed specifications/configuration per official condition.
- `prepare-probe --role ROLE --model-lock RELATIVE_LOCK --root ROOT` freezes the shared-provider probe input. `probe-gpu --role ROLE --root ROOT` runs only in a Slurm CUDA allocation and records observations. It does not mark any V gate verified.
- `freeze-runtime --root ROOT` records the actual CUDA environment, classifier model, source identities and disposable classifier probe. It precedes `initialize`, all tuning and all official training.
- Existing `prepare-data`, `generate-e1` and `generate-e2` commands produce the shared data/E1 and three E2 candidate pools. `prepare-tuning` locks the nine-run protocol; `train-tuning --strength S --seed SEED` executes one full shared run; `select-tuning` verifies all nine before selecting.
- `freeze-selected-pool` preserves the selected candidate manifest bytes. `prepare-run --run CONDITION/SEED` freezes each official descriptor. `bind-selected` verifies/promotes the three selected executions together. The alternative `plan-fresh-e1e2 --reason TEXT` freezes a fresh-three-seed decision before `train` calls; it cannot coexist with reused bindings.
- `generate-e3 --variant A1 --reference --descriptor JSON` creates the separate CADS bank. `mine-confusers --model-lock RELATIVE_LOCK` extracts the pinned DINO CLS features and publishes cached mining arrays. `generate-e3 --variant A1|A2|A3 --descriptor JSON` freezes final generation and its hybrid pool. The generation descriptor has strength, model_lock, model_sha256 and the private dataset_root. A1 acceptance uses the bank hashes; A2/A3 additionally use the cached confusers. A4 descriptors reference the exact A3 pool and record the unchanged anchor/step counts.
- `train --run CONDITION/SEED --root ROOT` executes the common schedule with epoch-boundary recovery. SIGUSR1/SIGTERM request a stop after the current epoch commit; an interrupted stage does not publish completion. Schema 3 checkpoints include Mixup state and a complete CPU-serialized best-epoch snapshot. Incompatible earlier schemas are rejected.
- `evaluate --run CONDITION/SEED --root ROOT` exports validation/test from the frozen official best checkpoint. E1E2 reuse requires the whole-triplet binding. Training's immutable `training_metrics.json` remains in the checkpoint lock; root `metrics.json` is finalized and locked by evaluation. Evaluation never rewrites the training snapshot.
- `report --root ROOT` requires all eighteen official evaluation locks, recomputes rankings/metrics from raw outputs and publishes the main/ablation aliases and three-seed aggregates. Eligible individual evaluations do not wait for the other runs.

Slurm preparation uses `freeze-array --name NAME --tasks JSON --root ROOT`. Each task has `id`, `argv`, `dependencies` (relative lock path to SHA-256) and `outputs` (authoritative locks required for completion). Array order is immutable. `execute-job` launches a new interpreter with the correct training seed and verifies dependencies before execution and output locks afterwards. `afterok` alone is insufficient.

`submit-array` accepts a verified site lock, explicit resource profile, predecessors and optional replacement submission reference. It requires separate scientific approval. The site evidence includes the resolved profile, verified maximum walltime and measured worst-epoch/checkpoint durations sufficient for the signal grace. Submission intents and returned JobIDs are retained separately; an unknown submission result must be inspected before retrying. No submission was performed during local tests. The shell wrappers take private Conda activation inputs from `GEOBENCH_CONDA_SH` and `GEOBENCH_CONDA_ENV`.

Local fixtures exercise these interfaces with simulated models/site observations. Actual component compatibility, memory/throughput, quota/site semantics, signal forwarding and requeue permissions remain deployment verification requirements.
